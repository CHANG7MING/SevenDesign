# Contributing

Thanks for helping improve SevenDesign.

## Guidelines

- Keep changes aligned with `DESIGN.md`
- Prefer semantic tokens over hardcoded values
- Maintain the same tone across homepage, app shell, and docs
- Avoid generic SaaS patterns and unnormalized component libraries
- Add new brands, archetypes, or components only when they materially expand the library

## Before You Submit

- Check [`PRE-FLIGHT-CHECKLIST.md`](./PRE-FLIGHT-CHECKLIST.md)
- Review [`FORBIDDEN-PATTERNS.md`](./FORBIDDEN-PATTERNS.md)
- Make sure new files are linked from [`LIBRARY-INDEX.md`](./LIBRARY-INDEX.md) and [`README.md`](./README.md)

## Suggested PR Shape

- one clear change set
- one new recipe or one implementation update per PR when possible
- include examples if you add new patterns
