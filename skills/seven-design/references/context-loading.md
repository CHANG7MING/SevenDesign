# Context Loading

SevenDesign loads context in four tiers:

| Tier | Load | Do not load |
| --- | --- | --- |
| `core` | entrypoint, `DESIGN.md`, `TOKENS.md` | unrelated scenario Skills |
| `selection` | Component Intelligence and compact source matrices | full registries, `llms.txt` |
| `implementation` | selected source, dependency notes, token references | unselected component sources |
| `review` | changed files, screenshots, selected review rubric | unrelated catalog entries |

## Rules

- Resolve the product task before selecting a library.
- React is the default; Vue / Nuxt requires explicit request or host evidence.
- Load React Bits or Vue Bits only when the expression layer is eligible and selected.
- Dense dashboard, editor, admin, and workspace surfaces do not load expressive Bits catalogs by default.
- Registry lookup is a narrow follow-up with at most eight results.
- The resolver output is the loading contract. Record the reason for every selected resource.
- When a runnable UI exists, add Visual QA after implementation; do not load it for text-only selection.

The goal is not to hide useful context. The goal is to prevent a complete catalog from becoming the default context for every task.
