# 交互测试

仅当结果依赖真实 UI、浏览器、设备或外部交互状态，而且代码检查和自动化测试无法提供可信判断时，读取本说明。

## 选择执行者

- 将可重复、路径明确、结果可观测的交互场景交给 Executor。
- 将产品取舍、主观视觉判断、弱判断标准和最终体验验收留在主线程。
- 同一个浏览器会话、设备、账号或外部环境同时只允许一个活动操作者。
- 只有在浏览器上下文、账号、设备或测试环境彼此隔离时，才并行执行交互测试。

## 编写任务包

除 Team Mode 的标准字段外，还要明确：

- 场景：需要验证的用户目标和起始状态。
- 环境：浏览器、设备、账号、数据与权限边界。
- 操作：最小必要步骤，不把探索过程伪装成固定脚本。
- 判断标准：可观察的成功结果、失败信号和允许误差。
- 证据：截图、日志、录屏、网络记录或状态快照中的最小充分集合。
- 清理：测试数据、临时状态、账号或环境需要如何恢复。

## 验收

- 优先复用代码、单元测试和静态检查已经证明的事实，不重复点击。
- 环境不可用、状态不确定或判断标准不足时，返回明确阻塞，不猜测成功。
- 主线程检查关键证据并完成最终验收；截图数量、工具和设备矩阵按风险决定，不设固定数量。
